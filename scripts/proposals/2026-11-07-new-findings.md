# HELD proposal 2026-11-07 (BL1, BL2) -- not applied, no application code edited
## BL1 unvalidated `metadata.tier` becomes the org's plan (amlkit/billing/service.py apply_subscription: `tier = config.tier_for_price(...) or metadata.get("tier")`)
A signed subscription event whose price is unknown but whose metadata carries any string sets `organizations.plan` to that string. `limits.org_state` then finds no such plan in PLANS and treats it as "a plan retired from the code", i.e. unlimited (legacy). Only someone who can write Stripe subscription metadata can trigger it, so it is a fail-open default rather than an external hole. Fix: accept the metadata tier only if it is in `PLANS` (else keep the current plan and log), and treat an unknown stored plan as the starter limits, not unlimited, unless the org is a true legacy org (`plan='trial'` with no `trial_ends_at`).
## BL2 malformed `items.data` makes the webhook return 500 for ever (apply_subscription -> `_sub_price_id`/`_period_end`: `items[0].get` on a non-dict)
Stripe retries a 500 indefinitely and the failed event is rolled back, so a poisoned event is retried for days. Guard with `isinstance(items, list) and isinstance(items[0], dict)`; on a structurally invalid event store it, log, and return 200 so Stripe stops.
