# HELD proposal 2026-11-12 (LM1) -- not applied, no application code edited
## LM1 mobile deactivate has no "last active MLRO" guard (amlkit/api/mobile.py api_admin_deactivate_operator, ~L1661-1672)
The web route (amlkit/api/routers/admin.py ~L543-553) refuses with "Cannot deactivate the last active MLRO. Promote another operator to MLRO first."; the mobile twin skips that check, so a sole MLRO (or whoever holds their mobile token) can leave the org with no active MLRO. Move the check into one shared helper (e.g. `cases.operators.deactivate_operator(conn, org_id, operator_id)` that does the org-scoped lookup, the last-MLRO guard, the UPDATE and the session revoke) and call it from both routes; add a regression test that exercises both. Also worth checking the same pairing for role demotion and for `reactivate`.
