each entry is dated; prior entries are never edited or reorganized.

- `entrypoint.sh` has caused two production incidents (litestream config syntax, then the Aug 19 crash-loop) but has zero automated coverage — `.github/workflows/source-canary.yml` only runs the Python test suite and upstream-source checks, nothing lints or exercises the shell recovery logic (restore-fails → fallback → legacy snapshot) that keeps being the actual point of failure.

### 2026-08-21

- Health check: **UNKNOWN (not DOWN)** — identical to yesterday, the sandbox egress proxy returned `403 Forbidden` on the CONNECT tunnel to `amlkit-720622408077.me-central1.run.app:443` before any request reached the app, for both `/` and `/about` (confirmed via `curl -v` and the proxy's own `recentRelayFailures` log, which shows repeated `connect_rejected` entries for this host). This is the second consecutive day this check has been unable to obtain real data — worth fixing at the environment/policy level (allowlist this host, or switch to Cloud Run's own uptime/metrics API) rather than reporting "unknown" indefinitely.
- Still open from yesterday, unchanged as of today: `backup_to_gcs.ps1` (hardcoded personal path, manual-only), the frozen legacy `gs://<bucket>/amlkit.db` fallback snapshot, `litestream.yml`'s missing retention/snapshot-interval + unverified restore, and `entrypoint.sh`'s untested recovery logic — none of these have been touched by the deploy-pipeline commits merged since (`#14`–`#17`, all scoped to Cloud Build/Artifact Registry auth).
- `amlkit/reporting/goaml.py` silently fills missing STR/SAR fields with plausible-looking placeholders (`"Grovisor Consultants"`, `"MLRO"`, `"N/A"` for account numbers, `"Unknown Entity"`) instead of failing loudly — a regulator-facing filing with a blank source account exports as `account_number = "N/A"` rather than blocking submission, and the module has zero test coverage (no `goaml`/`serialize_goaml` hits anywhere under `tests/`).
- `amlkit/reporting/goaml.py:84` builds `transactionnumber` from `int(datetime.now().timestamp())` (second-granularity, local time) while every other timestamp in the same function correctly uses UTC — two STRs exported within the same second collide on transaction number, and the local-vs-UTC inconsistency is its own latent bug.
- `amlkit/screening/kyt.py`'s structuring check sums *all* cash transactions in the 7-day window, including ones that already individually cleared `LARGE_CASH_THRESHOLD_AED` and fired their own `large_cash` alert — so a single large legitimate deposit plus one small unrelated transaction can trigger a `structuring` alert whose evidence (`total_aed`, `transaction_count`) misleadingly implies threshold-avoidance behavior that didn't happen.
- Deploy tooling has drifted onto two different registries: `scripts/deploy_gcp.ps1` and `scripts/cloud_shell_deploy.sh` still push `gcr.io/$ProjectId/amlkit:latest` (mutable tag, legacy Container Registry — which Google is sunsetting for new pushes), while the new `source-canary.yml` CI deploy pushes `${GCP_REGION}-docker.pkg.dev/.../amlkit:${{ github.sha }}` (Artifact Registry, immutable per-commit tag) — a manual deploy via either script no longer shares image history or commit traceability with what CI actually deploys.
- `amlkit/web/templates/str_builder.html` line ~55 calls `customer.full_name.split()[0]` unguarded for natural-person customers — a customer record with an empty/whitespace `full_name` (blockable via the onboarding form's `required` attribute, but not enforced at the DB layer for records created another way) throws `IndexError` and 500s the STR builder instead of showing a form error.
