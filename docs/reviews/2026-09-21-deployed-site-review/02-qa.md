# amlkit — QA lane findings

**Target:** exact deployed code running locally at http://127.0.0.1:8000 in production mode (`AMLKIT_BEHIND_PROXY=1`, `AMLKIT_DISABLE_AUTO_REFRESH=1`, no outbound network for sanctions sources / GDELT).
**Date:** 2026-09-21 · **Method:** gstack `/qa` phases 1–6 (orient → explore → document → wrap-up) with the webapp-testing reconnaissance-then-action pattern; Playwright (headless Chromium) for every browser flow, `httpx`/`curl` for the route census, mobile API and concurrency smoke.
**Evidence root:** `scratchpad/qa/` — scripts `flow_*.py`, `census.py`, `concurrency.py`; per-run logs `*-log.json` / `*.out`; 116 screenshots under `shots/` (referenced below as `shots/<file>`). Server stderr: `../server.log`.
**Accounts used:** the review MLRO from `creds.json` plus throw-away operators created via Admin (`qa.officer@…`, `qa.officer2@…`, and the validation-probe operators `not-an-email`, `bogus@x.test`). Data created: customers 1,3–33, reports 1–8, policy "AML Policy v1" v1–v2, one compliance deadline, 3 transactions, 4 mobile documents.
**Environment caveat:** the sandbox blocks outbound HTTPS (403 from the proxy), so every sanctions/PEP source and GDELT fails to fetch; only the bundled FATF jurisdiction list (26 rows) loads. The one direct DB edit I made (`UPDATE operators SET is_active=1 WHERE id=1`) was to recover from bug QA-02 below; nothing under `/home/user/amlkit` was modified.

## 5. Works well

* **Screening UI (Latin + Arabic):** "Osama bin Laden", "أسامة بن لادن", "Vladimir Putin" all run in ~50 ms; the result copy is honest — *"No match … screened against 0 candidate record(s); nothing scored at or above 0.85 … This screening has been recorded"* — and each run is written to the audit log with `datasets_used`. Empty/space-only name → "Enter a name to screen." XSS in the name is escaped.
* **Nationality / country typeahead:** 194 ISO countries from `countries.js`, searchable by substring (`"uni"` → UAE, UK, Tunisia, US), sets the hidden ISO code (`AE`), no matches for junk; used consistently on screen, onboarding and the counterparty field.
* **Onboarding happy path:** legal entity with two UBOs (60/40) → MEDIUM 25 with factor breakdown and a rendered UBO diagram; natural person with all factors → HIGH 80 / EDD with next-review date; Arabic name stored and searchable (`النور` finds the entity); duplicate reference rejected ("Reference 'QA-LEGAL-001' already exists"); UBO total >100 % rejected ("would be 125.0% (cannot exceed 100%)"); source-of-wealth/funds fields appear when risk = high.
* **Customer lifecycle:** tabs (Overview/Alerts/Monitoring/Case file/History) deep-link via hash; notes, signatures, transactions and adverse-media runs all land in the printable **evidence pack** with timestamps and operator names; **Close relationship** → CLOSED with 10-year retention date, **Reactivate** restores it; list search, CSV export (UTF-8, Arabic intact).
* **Transaction monitoring:** 75,000 AED cash from IR immediately raises `large_cash` and `high_risk_country`, surfaced on the dashboard and dispositionable (true/false positive) from the Monitoring tab; negative amounts and non-AED-without-FX are rejected with clear messages.
* **Adverse media failure handling:** network failure is reported honestly everywhere ("CHECK DID NOT COMPLETE — GDELT request failed: 403") and the dashboard explicitly says a failed check does not count as a check.
* **goAML export:** `GET /reports/{id}/export` downloads `goAML_STR_1.xml`; it **parses with lxml**, root `<report>` with report_code/entity_reference/submission_date/reporting_entity/reporting_person/reason/subject/transaction/attachments; `&` and `<b>` in the narrative are correctly escaped; amount/currency/transaction carried through. Edit-draft round-trips; submit via the real button flips to SUBMITTED and hides the edit link (backend gap is QA-03).
* **RBAC (officer vs MLRO):** officer is redirected from `/admin`, `/admin/compliance`, `/admin/rule-config`, `/audit`, `/console` with *"This action requires the mlro role; your account is officer"*; `/audit/export` → 403; POSTs to threshold, operator create/deactivate/reset-password, refresh, rescreen, rule-config → 403; policy upload, org-profile, report submit and customer close/reactivate are silently refused (verified no change). Officer nav hides Freeze Obligations/Admin; officer can still read reports/policies/customers and record notes (reasonable).
* **Auth hygiene:** session cookie `HttpOnly; Secure; SameSite=Strict`, CSRF cookie `Lax`; synchronizer-token CSRF verified (missing/wrong token → request dropped, nothing written); login rate limit 3/min per account + 10/min per IP returns 429; `MAX_CONCURRENT_SESSIONS=3` evicts the oldest session; password change requires the current password, enforces length/complexity ("must be at least 10 characters long"), shows "incorrect" for a wrong current password, reports "Password changed successfully", revokes all sessions, and the new password logs in; `/account/password` confirm mismatch → "do not match"; MLRO password reset and deactivation both sign the operator out of every session and a deactivated operator cannot log in; logout → `/login`, protected pages redirect, back button does not resurface data.
* **Admin:** goAML reporting-entity profile saves and pre-fills the STR builder; threshold validated (0–1, numeric) with "Currently overridden" / "engine default" state; operator create rejects weak passwords and duplicate emails (case-insensitive); policy upload validates real PDF, versions re-uploads (v1 → v2) and downloads the exact bytes.
* **Audit:** `/audit` page and `/audit/export` CSV (37+ rows) capture login, onboarding, screening (with lists used), risk assessment, refresh failures, report save/submit, dispositions.
* **Security headers:** CSP (`default-src 'self'`, no inline scripts), HSTS, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `X-Request-Id` on every response.

## 6. Top 3 to fix

1. **QA-01** — never let a jurisdiction list satisfy the "mandatory sanctions dataset" gate, and show failed sources as BREACH rows / a persistent banner instead of a one-time flash. Right now a firm can onboard and "clear" customers against zero names while the dashboard says lists are fresh.
2. **QA-04** — make the DB dependency thread-local (or `check_same_thread=False` with a per-request connection); intermittent 500s under ordinary parallel page loads will hit real users.
3. **QA-02 / QA-03** — block self/last-MLRO deactivation (and add a reactivate action), and reject `POST /reports` for reports whose status is not `draft`.
