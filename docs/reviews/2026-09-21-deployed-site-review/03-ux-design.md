# amlkit — UX / Accessibility / Design review (UX lane)

Reviewed against the exact deployed code running locally at http://127.0.0.1:8000 (production mode), logged in as the MLRO test operator. Method: (a) ui-ux-pro-max design intelligence (`ux-guidelines.csv` rule IDs cited as **UX-nn**, `ui-reasoning.csv` rows as **UIR-nn**), (b) gstack `design-review` audit dimensions + `review/design-checklist.md` (cited as **GS-…**), (c) amlkit-full-review UX backlog p31–p34, (d) Playwright capture at 1440x900 / 768x1024 / 390x844 with DOM-level checks (no axe-core available offline; manual DOM audit used instead), (e) WCAG contrast computed from the oklch tokens in `app.css`.

Artifacts:
- Scripts: `scratchpad/ux/capture.py`, `recheck.py`, `capture2.py`
- Raw data: `scratchpad/ux/results.json` (57 page×viewport captures), `recheck.json`, `capture2.json`
- Screenshots: `scratchpad/ux/shots/<page>@<viewport>.png` plus interaction shots (`focus_*`, `country_dropdown_open`, `usermenu_open@*`, `tablet_drawer_open`, `screen_arabic_result*`, `feedback_modal`, `dashboard_freeze_open`, `onboard_empty_submit`, `mobile_alerts_viewport`, `admin_mobile_viewport_operators`, `loading_state_button`, `skip_link_focus`, `dashboard_dark_mode`)

## 3. Design-system observations

**Tokens (`app.css:29-60`).** A genuinely good, coherent oklch system: one cool-neutral ramp (`--bg/--surface/--line/--line-soft/--ink/--ink-2/--ink-3`), one accent, five semantic hues at matched chroma/lightness (danger/warn/good/violet/terrorism, each with a `-soft` tint), brand orange, radius scale 8/10/16/20. Computed sRGB and WCAG ratios:

| Token | Hex | On `--bg` | Verdict |
|---|---|---|---|
| `--ink` | #101419 | 17.6:1 | AAA |
| `--ink-2` | #53595f | 6.8:1 | AA (safe for all secondary text) |
| `--ink-3` | #888d92 | **3.2:1** | **Fails AA for text** — used on 30+ selectors (labels, eyebrows, section labels, muted, tabs, tab-bar labels) |
| `--accent` | #006bbb | 5.2:1 (4.6:1 on `--accent-soft`) | AA |
| `--danger` | #b63b39 | 5.5:1 | AA |
| `--warn` | #b77610 | **3.6:1** | Fails for 11px tags; OK only as ≥24px bold |
| `--good` | #287c42 | 5.0:1 | AA |
| `--violet` | #6f5db9 | 5.1:1 | AA |
| `--terrorism` | #b34400 | 5.4:1 | AA |
| placeholder oklch 72% | #a1a5a9 | **2.4:1** | Fails |
| banner warn text oklch 45% | #814400 | 6.5:1 on warn-soft | AA |
| white on `--ink` / `--accent` / `--danger` | — | 18.5 / 5.5 / 5.7 | AA |
| hero `.l` (white @ .7 on ink) | #b7b9ba | 9.4:1 | AA |
| `--line` on `--surface` | #dfe1e4 | 1.28:1 | hairlines only; input borders are below the 3:1 UI-component threshold (UX-62 input affordance) |

Recommendations: (1) introduce `--ink-3` ≈ oklch(52%) for *text* and keep the 64% value as `--ink-4` for hairline/decorative use; (2) raise input borders to oklch(80%) so fields read as interactive (3:1); (3) add `--warn-text` oklch(50% 0.13 70) for small warn text; (4) placeholder oklch(58%).

**Typography.** Manrope (self-hosted, variable 200–800, preloaded) with `ui-monospace` for numerics — a good, non-generic choice for an Operate surface. Scale in use: 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14 / 14.5 / 15 / 16 / 18 / 24 / 26 / 28 / 32 / 34 / 36 / 48 / 68px — **20 distinct sizes**, many separated by 0.5px, which is arbitrary rather than a modular scale (UX-74 Font Size Scale; GS-Typography "scale follows ratio"). Recommend collapsing to 12 / 13 / 14 / 16 / 18 / 20 / 24 / 32 / 40 / 64 with `--fs-*` tokens, body 16px on phones (UX-67). Uppercase tracked labels are applied to *every* `<label>` (`letter-spacing:.04em; text-transform:uppercase`) — fine as a house style but combined with 12px/3.2:1 it is the single biggest legibility issue. Arabic: `dir="auto"` + `lang="ar"` + `.name-ar` (1.05em, Tahoma/Arial fallback) render correctly RTL in inputs and results (`shots/screen_arabic_result.png`: `direction: rtl, unicode-bidi: isolate`); Manrope has no Arabic glyphs so Arabic falls to Tahoma/Arial — consider self-hosting an Arabic companion face (e.g. IBM Plex Sans Arabic / Noto Naskh Arabic subset) for consistent weight.

**Spacing.** Panels 26px, list rows 16px, page-head margin 36px, gaps 16/18/20/24 — mostly on a 4px grid but not tokenised; ~120 inline `style=""` attributes across templates (e.g. `dashboard@desktop.inlineStyles` = 25, admin 40+) carry layout (`grid-template-columns`, widths, colours like `#d32f2f`). Recommend `--space-1..8` tokens and moving repeated inline grids (`compliance.html`, `audit.html`, `customer.html` tables) into named classes.

**Radius.** 8/10/16/20 hierarchy is coherent (buttons 8, inputs 10, panels 16, hero 20) — good; the floating alerts pill (999px) and avatar are intentional exceptions. Country dropdown uses 4px, off-scale.

**Components / consistency.** Two competing table idioms (`<table>` on evidence & freeze pages vs `.grid-table` everywhere else) — the `.grid-table` stacked-with-`data-label` phone pattern is excellent and should be the only one. Two button idioms (`button`/`.btn` tokenised vs freeze templates' Bootstrap classes). Two banner idioms (`.banner` vs freeze `.alert-info`). Tag component (`.tag` dot + uppercase) is consistent and readable but relies on colour+text (good, UX-37 satisfied). Empty states are consistent in structure (icon / title / text) but lack a primary action except on customers (UX-79 "message and action").

**Motion.** 140–180ms transforms on cards/drawer, 0.3s fade-in — within UX-8 range, transform/opacity only (UX-13), but no reduced-motion guard (#19). No `transition: all` anywhere — good.

**AI-slop scan (gstack category 9).** Present: gradient text wordmark (login/register), radial glow on primary CTAs and hero card, side-border callout (dashboard freeze panel), kicker/eyebrow above every H1, emoji as icons, ALL-CAPS CTA. Absent: purple gradients, 3-column icon-circle grid (the Home action cards are a 3-up grid but with real, distinct destinations), centred-everything, uniform bubbly radius, overused fonts, marketing buzzwords. AI-slop grade: **B-** (mostly product-specific, a handful of costume elements on auth screens).

**gstack-style category grades (design score).** Visual hierarchy B, Typography C (sizes/contrast), Spacing & layout C+ (inline styles, admin/compliance collisions), Colour & contrast C (token system A, application D), Interaction states D (combobox, modals, drawer, loading), Responsive C+ (phone patterns good; overlaps, evidence table), Motion B, Content B-, AI slop B-, Performance feel A- (self-hosted fonts, no external scripts, CSP-clean). **Overall ≈ C+**, dragged down by three blank pages and accessibility fundamentals rather than by visual taste.

## 5. Strengths (keep these)

1. **Coherent oklch token system** with matched-chroma semantic hues and a deliberate extra `--terrorism` hue documented in-CSS — a rare, thoughtful piece of design reasoning.
2. **Self-hosted Manrope with unicode-range subsetting, preload and `font-display: swap`**; no external scripts or fonts; CSP-friendly `data-action` event wiring instead of inline handlers.
3. **Arabic/RTL handled correctly** end-to-end: `dir="auto"`, `lang="ar"`, bidi isolation, placeholder in Arabic, screening input and result render RTL without mirroring the layout.
4. **Phone `.grid-table` stacked pattern** with `data-label` pseudo-headers — customers, audit, screening history and admin data-source tables degrade gracefully with zero horizontal scroll.
5. **Skip link, `aria-label`led navigation landmarks, `aria-expanded` on menu buttons, `aria-live` on feedback result, print stylesheet** — the accessibility scaffolding is present, it just isn't carried into forms/modals/comboboxes.
6. **Sensible empty states** on every list page with tenant-scoped copy ("No alerts in Review Firm DMCC"), plus a primary action on Customers.
7. **Regulatory copy is specific and honest** (24-hour rule breach banner, "This screening has been recorded — evidence that a check was performed", single-operator-mode disclosure) — the product speaks the compliance officer's language rather than marketing.
8. **Focus rings** on buttons, links, selects and sidebar items are a clear 2px accent outline (`shots/focus_onboard_tab4.png`); text inputs get a 3px accent-soft halo — only the underline variant is deficient.
9. **Loading affordance** (spinner + verb-in-progress label) on every long-running submit; four-eyes review notes surface inline where the decision is made.
10. Home action cards use real SVG icons and distinct destinations, and the mobile 4-tab bar respects safe-area insets — the phone IA is better designed than the tablet IA.
