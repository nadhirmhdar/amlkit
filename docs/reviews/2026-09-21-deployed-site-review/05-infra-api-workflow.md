| A1 | **Multi-instance Litestream = replica corruption risk (root cause class of the Aug-19 "decode page 7575: EOF" outage)** | `source-canary.yml:389` `--max-instances 10`; `entrypoint.sh:89` every instance runs `litestream replicate` against the same `gs://…/litestream/amlkit.db`; `backup-verify.yml:3-9` describes the corrupted-segment incident | Litestream requires exactly one replicating process per replica path. Any scale-out to ≥2 instances (a traffic burst, a deploy overlap, a health-probe storm) produces two writers to one LTX stream. Set `--max-instances 1`. | A2 | **CPU throttling starves Litestream between requests** | `source-canary.yml:378-390` has no `--no-cpu-throttling` / `--cpu-boost`; `--min-instances 0` | With default throttling, the litestream goroutines only get CPU while a request is in flight; WAL pages written by the last request of a burst may not be shipped before Cloud Run idles/kills the instance (10 s SIGTERM grace). ## C. Workflow pipeline validation (Step 12) — amlkit's real state machine vs. the intended flow

Sources: `amlkit/api/app.py` routes (`:943-3029`), `amlkit/cases/review.py`, `amlkit/cases/manager.py`, `amlkit/cases/freeze.py`, `amlkit/match/engine.py:372-440`, `amlkit/db.py:297-640`, `amlkit/reporting/goaml.py`, `scripts/auto_rescreen.py`, `amlkit/cases/scheduler.py`.

### C.1 State machine as implemented (Mermaid)

```mermaid
stateDiagram-v2
    direction LR

    state "Customer" as C {
        [*] --> active: POST /customers (manager.onboard → screen)
        active --> closed: POST /customers/{id}/close (close_relationship, 8y retention)
        closed --> active: POST /customers/{id}/reactivate (MLRO only, NO rescreen)
        closed --> [*]: purge_expired (retention_until < now AND no unresolved freeze)
    }

    state "Screening / Alert (alerts.status)" as A {
        [*] --> open: engine.screen hit (dedupes on open alert per entity+customer)
        open --> open: rescreen_all every refresh (/system/refresh, /admin/rescreen, auto_rescreen.py) — active customers + ALL ubo_links
        open --> true_positive: propose_disposition(true_positive) — narrative required, NO second reviewer
        open --> escalated: propose_disposition(escalated) — narrative required
        open --> pending_review: propose_disposition(false_positive) [needs_independent_review AND NOT single_operator_mode]
        open --> false_positive: propose_disposition(false_positive) [single_operator_mode] (independent_review='single_operator')
        open --> false_positive: POST /alerts/bulk-dismiss (bulk_dismiss_alerts) — BYPASSES four-eyes, default reason name_coincidence
        pending_review --> false_positive: POST /alerts/{id}/confirm agree=yes (different operator)
        pending_review --> escalated: POST /alerts/{id}/confirm agree=no (different operator)
        pending_review --> open: propose_disposition(status='open') — 'open' is in DISPOSITIONS; effectively withdraws the proposal
        true_positive --> [*]: TERMINAL (review.py:195 "Cannot re-disposition")
        false_positive --> [*]: TERMINAL
        escalated --> [*]: TERMINAL — never linked to report outcome
    }

    state "Freeze obligation (freeze_obligations.status)" as F {
        [*] --> pending_execution: auto from true_positive with sanctions/PF/terrorism topic (_auto_create_freeze_if_required)
        pending_execution --> executed_pending_report: POST /freeze-obligations/{id}/execute
        executed_pending_report --> reported: POST /freeze-obligations/{id}/file-ffr → creates reports row (FFR, status=draft)
        pending_execution --> resolved: /resolve (delisted | false_positive | authority_clearance)
        executed_pending_report --> resolved: /resolve
        reported --> resolved: /resolve
        resolved --> [*]
    }

    state "Report (reports.status)" as R {
        [*] --> draft: POST /reports (STR|SAR|FFR|PNMR) or file-ffr
        draft --> submitted: POST /reports/{id}/submit — local flag only; goAML XML is downloaded via GET /reports/{id}/export and uploaded to goAML by hand
        submitted --> [*]: TERMINAL — no withdrawn / amended / rejected-by-FIU
    }

    A --> F: true_positive + sanction topic
    A --> R: escalated / true_positive → operator opens /reports/new?alert_id (manual, not enforced)
    F --> R: file-ffr
    C --> A: onboard + each rescreen
```

`AMLKIT_SINGLE_OPERATOR_MODE=1` (`review.py:51-58, 200-215`) **removes the `pending_review` node** and the two `confirm` edges: `false_positive` is applied immediately and stamped `independent_review='single_operator'`. Nothing else changes — `true_positive`/`escalated` never had a second reviewer in either mode.
