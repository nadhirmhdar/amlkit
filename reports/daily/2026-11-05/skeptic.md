A small table in `review.py` fixes it, and a test that every (status, code) pair either passes or is refused explicitly would keep it fixed.
2. **The workflow finding is a process one.** Two roles flagged CR-40/CI1 independently, which shows it is easy to see; it is also easy to introduce, because the secret was added to make a check pass. The usual remedy is a workflow lint (for example "no `secrets.*` in a job that runs on `pull_request`") as a test, like the new `test_workflow_env.py` already does for the deploy job.
