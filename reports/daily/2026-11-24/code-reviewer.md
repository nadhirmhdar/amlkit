**Findings:**
- **CR-52 (LOW, CONFIRMED): non-string JSON values crash the new route with a 500.** `body.get("org_name") or ""` is followed by `.strip()`, so a number, list, dict or `true` for `org_name`, `name`, `email` or `password` raises `AttributeError` (or `TypeError` in `check_new_password` for a number) outside the `except ValueError`. Probed: `org_name=123`, `["x"]`, `true`; `name=123`, `{"a":1}`; `email=123`; `password=123` all returned 500 "Internal Server Error". A list for `password` and `null` for `email` were handled (400). Reachable only with `ADMIN_API_SECRET`, so no external exposure, and nothing was written on those paths. The same pattern exists in `/system/create-operator` (pre-existing). Fix: coerce with `isinstance(x, str)` checks and return 400.
- **CR-53 (INFO, CONFIRMED, behaviour to know): the "N-day trial" is not enforced while billing is off.** `check_limit`/`org_state` are a no-op unless `stripe_client.load_config()` returns a config, which needs `AMLKIT_BILLING_ENABLED` plus `STRIPE_SECRET_KEY`. Probe 3 shows an expired trial org keeps creating operators. CLAUDE.md says this ("only enforced when billing is switched on"), so it is documented, but anyone granting a trial today gets unlimited access until billing is enabled; at that point the org is moved to Starter limits and a 7-day grace.
- **CR-54 (INFO, CONFIRMED): CLAUDE.md omits that `days` defaults to 14** when the field is missing (code: `body.get("days", 14)`). It also says the new route needs no card but does not mention that no verification email is sent and the password is chosen by the caller.
