## What the team missed
1. **The enumeration fix changed the content but not the work done.** This is the same pattern as the old login timing defence: `auth.login` hashes a dummy value for unknown emails so the response times match, and the new sign-up path did not copy that lesson. The code already contains the right idiom; reuse it.
2. **Two sign-up doors, two behaviours, still.** The invite-gated door tells code holders an address exists (by design), the open door does not. If the invite path is meant to stay, say so in CLAUDE.md; if it is to be retired, retire it.
3. **The sanctions-refresh fix is invisible to CI.** `continue-on-error: true` on the scheduler step means a permissions failure keeps the old 20-hour schedule and the run stays green. Add a final step that reads the job back and fails (or at least warns loudly) when the schedule is not `0 */4 * * *`. Compliance asked a human to check; a one-line `gcloud scheduler jobs describe` in the workflow would remove the manual step.
4. **Four-hourly refresh and the freeze clock are now two separate numbers.** CS-13 (clock starts at disposition) is unchanged, so the time budget is ingestion (up to 4 hours) plus review. Worth restating in the product's help text.
5. **Eight days from first to last wave, nothing above Low today.** The loop worked. Remaining Mediums are decisions or a feature gap (CS-13, CS-14, 3.1, CR1, CS-24 residual), not defects.
